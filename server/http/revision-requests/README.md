# revision-requests

HTTP rub zahtjeva za doradu: `POST /api/v1/revision-requests/{action}` (SRV-2006, DAN-314 2f; radnje `create`, `respond`, `accept`, `reopen`, `rereview`, `withdraw`, `list`). Tanki rub nad funkcijama `collaboration.*_revision_request`: kolačić određuje sesiju, tijelo mora biti točno kanonski JSON s točno ključevima radnje, neispravan id čita se kao tuđi (403), a tko smije i koji je prijelaz dopušten odlučuje baza. Zastarjeli brojač je odgovor 409 `{outcome: "conflict", …}`, prijelaz koji stanje ne dopušta je 409 `not_allowed`.

Port Ductus granice `server/collaboration/revision-requests.ts`; ta kopirana datoteka ostaje izvan karte područja (`server/collaboration` nije područje, pa je `server/http` ne smije uvoziti).

`send.ts` je rub `POST /api/v1/revision-send` (`collaboration.revision-send.post`, SRV-ED43-DORADA-POSALJI, BLOK ED-43): student vlasnik šalje doradu na pregled. Tijelo je točno kanonski JSON `{documentId, message}` (poruka nastavniku ili `null`), odgovor `{round}`. Odlučuje `collaboration.send_revision` (migracija 20261220180000): sljedeća runda samo ako je od prethodne runde otvoren ili ponovno otvoren zahtjev za doradu, inače 409 `not_allowed` (i na predanom radu), pa ponovljeno slanje nikad ne preskače rundu. Nastavnik rada dobiva 403, svi ostali, nepostojeći rad i neispravan id 404. Zasebna ruta, a ne nova radnja `revision-requests`, jer bi nova radnja promijenila postojeće sheme te rute (`contracts:breaking`).
